## Design north star (judgment calls)

This box is a safe, passive routine for a 2-year-old: cognitive calm, developmental
consistency, and stress-free entertainment. Prefer those over engagement metrics.

1. Slow pacing. Library is Little Bear, Oswald, and Harry. Do not add high-stimulation titles.
2. Predictability over novelty. Closed ~140-episode library of the same three friends.
3. Gentle environmental connection via filename tags and the scheduler.
4. Zero decision fatigue: no menus, episode lists, search, thumbnails, or Up Next.
   Power on plays; channel buttons only switch which friend is on.

## README overrides (single source of truth after T0)

These take priority over the original README. T0 amends the README to match.

1. **Internet is allowed, never for content.** Drop "LAN-only, no WAN" and the outbound
   firewall. The Pi may use the internet for NTP, system updates during maintenance,
   and fetching episode titles/descriptions during maintenance. Every show comes from
   the local library. Playback never fetches, streams, or depends on anything online.
   If the internet is down, the TV works exactly the same.
2. **Survive a pulled plug.** No graceful shutdown. Read-only card; the application
   writes nothing to disk while running. See Power-cut safety below.
3. **Episode tags are generated by a tool**, not by hand. `python -m tv90 tag` fetches
   titles/descriptions and assigns daypart, season, and holiday tags by keyword matching.

## Architecture

Ports-and-adapters. Scheduling logic is pure and fully testable.

- **Domain (pure, no I/O):** episodes and tags, filename parsing, time-of-day weight,
  season weight, holiday calendar and multiplier, recency, combined weight, timeline
  building, channel lineup, "what is airing now", keyword-to-tag rules. No clock,
  filesystem, environment, network, or randomness except through injected collaborators.
- **Ports:** `Clock` (current time plus trusted-time status), `DurationIndex`,
  `MediaProber`, `Player`, `TvPower`, `LibrarySource`, `EpisodeMetadataSource`.
- **Adapters:** mpv IPC, ffprobe, cec-client, filesystem library, system clock,
  online metadata client. Each has an in-memory fake used by tests.
- **Application:** TV controller and maintenance commands.
- **Interface:** Flask web remote and CLI entry points; they call the application only.
- **Composition root:** one `main` module that wires real adapters; nothing else
  constructs them.

Use classes for state/roles (controller, timeline, lineup, adapters, frozen dataclass
value objects). Use plain functions for pure calculations (Gaussian). No classes that
only wrap one function. No inheritance hierarchies where a protocol and composition
will do. Each weight factor is its own small strategy object; final weight is a product
of independent, separately tested parts.

## Power-cut safety

- `setup.sh` enables the overlay filesystem and write-protects boot.
- Episodes live on their own partition, mounted read-only at runtime.
- TV service writes nothing to disk: no history, caches, state, or log files.
  Logs to journal with `Storage=volatile`. mpv writes no watch-later or cache.
- `tv90-maintenance on|off` is idempotent and prints the current mode.
- Trusted clock before tuning in. Hold the calm slate until network time is
  synchronised. After a configurable timeout (default 3 minutes), begin playback
  with the system's best-known time, show "clock not synced" on the web remote,
  and re-tune when sync arrives.

## Library maintenance tools

Run only in maintenance mode.

- `python -m tv90 tag`: identify episode, fetch title/description, keyword-match tags,
  rename to README §4 scheme. Dry run default; `--apply` renames. Existing tags are
  never removed or changed. Cache metadata next to the library.
- `python -m tv90 index`: probe durations with ffprobe, write duration index on the
  library partition. Runtime reads the index; missing files are probed in memory
  and never written back.

## Decisions already made (record in docs/DECISIONS.md during T0)

- Web framework: Flask.
- Timezone: configurable, default `America/Vancouver`.
- Seeding: stable hash (`hashlib`) of date, channel, and slot start time. Not `hash()`.
- Timeline purity: a day's timeline is a pure function of date, channel, library, and
  configuration. Recency is computed from the timeline being built, never persisted.
- Empty weights: relax recency block first, then the penalty. A slot is never empty
  while the show has any playable file.
- Season weight: named per-file multipliers (in-season highest, evergreen lower,
  wrong-season small but non-zero), tuned so in-season takes ~80% of airings on a
  balanced mix. Verify with a simulation test.
- Holiday windows: CH 04 opens `HOLIDAY_LEAD_DAYS` (default 3) before the first event
  day and closes at the end of the last event day. Christmas event days are Dec 24–25.
- Layer A multiplier: linear ramp 1.25 at 14 days out to 1.50 on event days. Outside
  lead-up, holiday-tagged cartoons are down-weighted like wrong-season.
- CH 04: same timeline builder; pool is the active holiday's movies; time weight
  fixed at 1 unless a movie carries a daypart tag.
- Night lock: an episode may start before 21:00 and be cut off; at 21:00 TV standby
  and input ignored until sign-on. Outside the broadcast day the player holds the slate.
- Channel down wraps in the mirror order of channel up.
- Volume resets to a configured default on every start.
- `setup.sh` installs `ffmpeg` and `cec-utils` in addition to README packages, enables
  network time sync, and does not configure an outbound firewall.
